# AI 翻译与校对辅助（ai-assist）

## Overview

在 jpsub 既有 `ai.py` 翻译能力之上，补齐「烤肉汉化排版」翻译界面中有而 jpsub 缺失的小项：多组 API 配置预设、术语表自动识别角色名、失败批次续翻、AI 校对，以及翻译用量统计与接口异常的友好提示。既有系统提示词、并发翻译、编号校验、额度/审查识别等能力保持不变。

## Requirement: 多组 API 配置预设

用户可保存/切换多组 API 配置（名称 + api_base + api_key + model），翻译时选用其中一组，而不必每次手改 `.env`。预设持久化到用户配置目录，与既有 `.env`/环境变量/命令行参数的优先级关系明确（命令行 > 环境变量 > 预设 > `.env`）。

### Scenario: 保存并切换预设

- WHEN 保存两组预设「中转A」「官方B」并选择「官方B」执行翻译
- THEN 本次翻译使用「官方B」的 api_base/model，另一组不被使用

## Requirement: 术语表自动识别角色名

除既有手动术语表（`词=译` 行式文件）外，支持从原文自动识别候选角色名：单独成行、长度 ≤12、无空格/标点/斜杠/冒号/引号、不以句末标点结尾、出现次数 ≥2。按出现频次取前若干条，供用户确认后加入术语表。自动识别的结果须可由用户编辑/剔除。

### Scenario: 自动识别高频角色名

- WHEN 原文中「拓也」多次单独成行出现且符合名字特征
- THEN 术语表候选包含「拓也」，而普通台词句不被当作候选

## Requirement: 失败批次续翻

批量翻译中若某批失败，已完成批次的结果予以保留；用户可「从失败批次继续」，仅重发失败批次及其后的批次，不重复请求已成功批次。

### Scenario: 从失败批次继续

- WHEN 10 批中第 4 批失败，用户触发续翻
- THEN 第 1–3 批不重新请求，翻译从第 4 批继续

## Requirement: AI 校对

对已完成翻译的条目再次调用 AI 校对：保持时间轴与条目数不变，仅修正错译、漏译与语气，模型未返回的条目保留原译文。校对后译文写回 `segments.json`，可撤销到校对前。

### Scenario: 校对不改时间轴

- WHEN 对已有译文的字幕执行 AI 校对
- THEN 条目数与各条 start/end 时间轴不变，仅文本被修正
- AND 模型未返回的条目保留原译文

## Requirement: 翻译用量统计（持久化）

累计并持久化每次翻译请求的 prompt/completion token 用量与估算费用，程序重启后仍可查询。在既有内存统计（`ai._USAGE`）基础上落盘，提供可查看入口。

### Scenario: 重启后仍可查询用量

- WHEN 完成一次翻译后退出并重启程序
- THEN 仍能查询到此前累计的 token 用量与估算费用

## Requirement: 接口异常的可读提示

当接口返回非 JSON 的错误响应（尤其是整页 HTML：Cloudflare 拦截页、502/503/504 网关错误页等）时，向用户给出说明**真实原因**的可读提示，而非直接抛出整页 HTML 或 `HTTP 502: <html>…`。提示须根据响应的真实状态码与内容判定原因（如「网关错误，后端故障」/「被 Cloudflare 拦截，可能需更换端点」），不得给出与实际原因不符的笼统兜底话术。

### Scenario: HTML 错误页转为可读提示

- WHEN 接口返回状态 502 且响应体为 HTML 页面
- THEN 用户看到说明真实原因（网关/后端故障）的可读提示
- AND 提示中不出现整页 HTML 源码

### Scenario: 提示如实反映原因

- WHEN 接口返回 Cloudflare 拦截页（HTML 且含拦截特征）
- THEN 提示指向「被拦截」，而非「额度不足」等无关原因

## 不变量

- 既有翻译行为、并发策略、缓存与写回 `segments.json` 的格式不变。
- 未启用新能力时，翻译命令的输入输出与现在一致。
