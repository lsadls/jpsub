# 字幕时间轴正确性（subtitle-timeline）

## Overview

`jpsub` 生成字幕（ASS/BCC）时，时间轴由「抽帧 → 关键帧选择 → OCR 文本 → 段构建 → 长文展开」链路决定。百度 OCR 批量通道把多帧纵向拼成一张图（`_stitch`）一次请求识别，再按帧归属拆回各帧（`_run_stitched`）：含位置版接口按行 `location.top` 的 y 坐标切分，无位置版接口按分隔带内的白色帧编号切分。本能力规定：批量拼接的帧编号渲染与切分必须与操作系统无关，任何切分失败都必须被检测并降级，不得把整批文本误并入单帧，从而保证各平台生成的字幕时间轴一致且正确。

## Requirement: cross-platform-frame-markers 跨平台帧编号渲染

`_stitch` 在相邻帧之间绘制黑色分隔带，并在其中为第 1..n-1 帧绘制白色帧编号（第 0 帧上方无编号）。编号绘制所需字体按跨平台候选列表依次尝试（覆盖 Windows、Linux、macOS 常见系统字体路径），全部不可用时使用 Pillow 内置默认字体；不得因某一平台的 Linux 字体路径缺失而跳过编号绘制，也不得新增第三方依赖。

### Scenario: 系统字体不可用时仍绘制编号

- WHEN 所有候选字体路径均不存在，调用 `_stitch` 拼接 n>1 帧
- THEN 图像中第 1..n-1 帧的分隔带区域出现编号文字像素
- AND 绘制过程不抛异常

## Requirement: marker-split-failure-fallback 编号切分失败防护

无位置版接口按编号切分时，若一次批量请求返回的行中没有任何行匹配区间编号（1..n-1）且批内帧数 n>1，则该接口切分不可信：不得把返回文本全部归入第 0 帧，而应视为该接口失败并尝试下一个批量接口；所有批量接口均不可用时退回逐帧识别。含位置版接口按 y 坐标切分，不受此条约束。

### Scenario: 无编号返回触发接口降级

- WHEN 无位置版接口对 n=4 的拼接图返回的行不含任何区间编号
- THEN 该接口的切分结果不被采用
- AND 流程尝试下一个批量接口，或全部失败时退回逐帧识别

## Requirement: monotonic-timeline 时间轴单调正确

在给定关键帧序列与各帧文本后，生成的段满足：各段 `start` 严格递增且首段 `start` 为 0（或命令行指定起点）；不再出现大量句子被压缩进数秒区间、随后产生数百秒空洞的错误分布。Windows 与 Linux 对同一输入产生一致的时间轴。

### Scenario: 段起点单调递增

- WHEN 用修复后的各帧文本构建段并展开长文
- THEN 段列表按 `start` 升序且相邻段 `start` 严格递增
- AND 首段 `start` 为 0
