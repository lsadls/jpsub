# Outcome

`jpsub` 具备「烤肉汉化排版」工具的全部自研字幕能力（不含其依赖 jpsubwin 的部分），使 jpsub 用户无需切换到另一套工具即可完成现成字幕文件（SRT/ASS/TXT）的导入、合并去重、排版转换、AI 翻译与校对，并复用既有的 render/edit/烧录/投稿链路；同时补齐翻译用量统计与接口异常的友好提示。

# Scope

## 背景：烤肉自研能力盘点（不含 jpsubwin 依赖）

烤肉（`/mnt/w/share/dev/烤肉汉化排版`，`字幕合并工具.html` + `server.py`）自身功能，本次作为参考实现：

- **A 字幕文件工程**：解析 SRT/ASS/TXT，编码自动识别（BOM / utf-8 / gb18030 / shift_jis / euc-kr / big5）；按间隔上限合并条目、仅合并相同样式、智能去重（前缀相似 / 模糊子序列 / LCS）；排版转换（空格与换行 → `\N`）；导出 SRT/ASS/TXT。
- **B AI 翻译能力**：多接口预设、术语表（手动「词=译」+ 自动角色名提取）、上下文轮次、JSON 与 `%%` 双协议、回显检测、失败批次续翻。
- **C AI 校对**：对当前译文再送 AI 校对（烤肉 `proofreadCurrentTranslation`）。
- **D 本地服务**：token 用量与调用统计、把中转站 HTML 错误页转成人话、LLM CORS 转发代理、视频流式上传、项目/任务管理、抽帧。

其依赖 jpsubwin 的部分（OCR 抽取、niconico 下载）不在本次范围。

## 与 jpsub 已有能力的重叠（只作参考，重写/补缺）

jpsub `ai.py` 已有：系统提示词、术语表替换（`_glossary_sub`）、历史裁剪（`_trim_history`）、并发翻译、编号校验（`_parse_reply_lines`）、额度/审查错误识别、标点规范化、**内存级 token 统计（`_USAGE`，仅结尾打印）**。B 段本次只补 jpsub 缺失的小项；D 段的 token 统计是「把已有内存统计持久化/可查询化」，而不是从零新增。

# Non-goals

- 不移植烤肉依赖 jpsubwin 的部分（OCR、下载、`run_task` 调用 `jpsub.cli extract`）。
- 不直接复制烤肉的浏览器 JS 实现；重叠能力在 jpsub 侧重写。
- 不改动 jpsub 既有 OCR 流水线、打码、烧录、投稿行为。
- 不引入新的第三方运行时依赖，除非任务明确要求。
- 不保留烤肉的单文件 HTML 形态本身。
- D 段不做 **LLM CORS 转发代理**与**视频流式上传**（jpsub 翻译在 Python 侧发起、视频在本地文件系统，二者在 jpsub 架构下无对等需求）。

# Acceptance examples

- A1：导入一份无 BOM 的 Shift-JIS `.srt`，解析出的原文全部为正确日文、无 `U+FFFD`，条目数与时间块数一致。
- A2：导入一份同一句被拆成多条、后条以前条为前缀、间隔均 ≤3 秒的 `.srt`，这些条目合并为一条，`start` 取首条、`end` 取末条、文本取最完整者。
- A3：两条相邻字幕文本相同但间隔超过上限时保持独立，不被合并。
- A4：一条单行短名字（长度 ≤12）并入前组后立即封组，其后紧跟的无关台词不被并入前组。
- A5：对文本 `第一行 第二行\n第三行` 执行排版转换，结果为 `第一行\N第二行\N第三行`，且 `{\pos(1,2)}` 等标签内容不被替换。
- A6：把一份 SRT 导入为工作目录 `segments.json` 后执行 `jpsub render`，成功产出 `.ass`，字幕时间与文本与导入内容一致。
- A7：把合并去重后的字幕导出为 SRT，输出为带 BOM 的标准 SRT（`HH:MM:SS,mmm`），条目数与合并后组数一致。
- B1：术语表设定「拓也=拓也」后翻译，译文中该词按术语表统一，不被模型自由改写。
- B2：模型以 JSON 数组或 `%%` 分隔两种任一格式返回时，翻译结果均能正确解析并一一对应。
- B3：模型在一批中回显原文（未翻译）时，该批被判为无效并触发重试/缩小批处理，而不是把原文当译文写入。
- B4：一批翻译失败后，从失败批次继续，已完成批次的结果保留、不重复请求。
- C1：对已有译文执行 AI 校对后，时间轴与条目数不变，仅译文文本被修正；模型未返回的条目保留原译文。
- D1：翻译完成后可查询到累计的 prompt/completion token 用量与估算费用，且在程序重启后仍可查（持久化）。
- D2：接口返回带 HTML 的错误页（如 502/503/504 或 Cloudflare 拦截页）时，用户看到的是说明真实原因的可读提示，而非整页 HTML 或 `HTTP 502: <html>…`。

# Constraints and invariants

- jpsub 是 Python 包（`jpsub/` 模块 + `jpsub` CLI 子命令 + 浏览器主页 home/edit/mask），移植须融入既有架构。
- 既有工作目录数据层为 `segments.json`（`jpsub/handoff.py`），译文快照存于其中；导入的字幕须与之同构。
- 既有 AI 翻译在 `jpsub/ai.py`（Python）；重叠能力重写时应复用/扩展 jpsub 侧实现，避免逻辑分叉。
- 程序在不启用新能力时行为与输出保持不变。
- 错误提示须如实反映接口返回的真实状态（不得给出与实际原因不符的兜底话术）。

# Verification expectations

- 静态与单元级：解析/编码识别/合并/排版转换/导出对照烤肉参考实现的行为，逐项用构造用例验证。
- 端到端：导入 SRT → `jpsub render` 产出 ASS；导入后 `translate` 在有 API 时产出译文、无 API 时保持既有报错行为。
- AI 能力：在 mock/无 API 环境下验证解析、回显检测、失败续翻与校对的控制流；不依赖真实付费接口。
- 回归：既有 `extract`/`run`/`mask`/烧录命令的输入输出不变。
- 错误提示：构造返回 HTML 错误页的响应，验证提示说明真实原因（状态码语义 / Cloudflare 拦截），且不出现整页 HTML。
