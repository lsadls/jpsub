# 目标

`jpsub` 能自动把 AI 拓也类视频画面里的**敏感汉字**（画面内烧录/绘制的日文文本中的敏感词）用遮挡块盖掉，产出与既有手工打码等效的结果，不再需要逐帧手工框选。

# 范围

- 自动定位画面中的汉字文本：优先调用百度 OCR **含位置版**（`accurate_general` / `general`）取行框并切出敏感词框；含位置版额度/可用性用尽后降级为算法定位（见 D4、D8）。
- 敏感判定：以独立敏感词清单为准（见 D3、D7），**复用工作目录已有的 OCR 原文**（`segments.json`）判断哪些时间段出现敏感词，不额外做全量逐帧 OCR。
- 输出与既有打码链路同构的条目（`start`/`end`/`x`/`y`/`w`/`h`/`effect`/`vol`），落盘到独立文件，由既有 `jpsub maskapply` 应用。
- 入口：既有 `jpsub mask` 上的新开关（非交互），与另一 change 的 `--auto`（自动去人）并存（见 D5）。

# 非目标

- 不做背景重建/inpainting 合成，只做区域遮挡覆盖。
- 不改变既有手工打码行为：`jpsub mask` 选取器与 `jpsub maskapply` 的既有行为与输出保持不变。
- 不改动 `masks.json` 字段格式与 `MaskEntry`/`parse_masks`/`save_masks` 实现。
- 不处理音频、不改动翻译/字幕生成流水线；不自动并入 `jpsub run` 主流程，需用户显式执行新开关。
- 不做自动合并或写回手工 `masks.json`：自动结果写独立文件，是否合并由人工决定。
- 不新增百度 OCR 接口，不改动 `_call` 的既有传参、语言设置、额度状态文件机制与 QPS 重试逻辑。

# 验收示例

- 对参考视频执行 `jpsub mask --sensitive`（工作目录含已生成的 `segments.json`），产出 `<工作目录>/.jpsub/masks.sensitive.json`，内容可被 `jpsub.mask.parse_masks` 解析：每条含合法 `start`/`end`（start<end）/`x`/`y`/`w`/`h`（w、h>0）/`effect`，且 `effect` 为 `color:000000`、`vol` 为 1.0。
- 对参考视频，自动结果与人工基线在时间与空间上对齐：人工 `masks.json` 中**可被词表解释**的条目（定义为：存在与该条目时间区间相交、且其 OCR 原文 `text` 含词表内词的字幕段）里，≥70% 存在与之时间区间相交且像素框相交面积>0 的自动条目。（词表先补入参考片画面上实际出现的变体写法后复测，阈值仍取 70%；实测依据见「验证预期」。）
- 运行前后人工 `masks.json` 的 sha256 不变，且自动结果只写入 `.jpsub/masks.sensitive.json`（不覆盖任何既有文件）。
- 以 `--sensitive-locate algo` 强制走算法定位时命令成功结束并产出可被 `jpsub.mask.parse_masks` 解析的合格掩膜：其框数不少于本次命中段数的一半；所有框的时间区间均落在命中段内；单刻同时覆盖画面面积占比 <15%（不整块覆盖画面）。
- 用自动掩膜执行 `jpsub maskapply` 成功输出视频，输出视频时长与帧率与源一致，抽帧可见敏感汉字被遮挡块覆盖。

# 约束与不变量

- 自动结果必须能被 `jpsub.mask.parse_masks` 解析，并可由 `jpsub maskapply` 直接应用。
- 手工 `masks.json` 不得被自动流程覆盖、删除或改写。
- 保守优先：不得把非敏感文字或大面积画面整块误盖；不确定时宁可漏框。
- 检测结果必须可人工复核（人类可读 JSON，可手工增删改）。
- 复用既有模块：`jpsub/mask.py`（`MaskEntry`/`parse_masks`/`save_masks`/帧抽取）、`jpsub/ocr.py`（`BaiduOcrEngine`）；新增逻辑放新模块（如 `jpsub/sensitive.py`），不修改既有函数签名，避免与另一 active change（`remove-weird-man`，同为 `jpsub/mask.py`、`jpsub/cli.py` 区域）产生无法合并的冲突。
- OCR 额度必须省用：正常路径下每个被定位的画面只发一次含位置版请求，同一时刻的帧只识别一次；已有 OCR 文本直接复用。

# 决策

- D1：验证素材使用用户指定的 `output/AIの力で拓也に保育園を開園させた_sm40378479/AIの力で拓也に保育園を開園させた.mp4`（640×360、约 30fps、1120.15s）与其手工 `masks.json`（39 条，全部 `color:000000`/`vol 1.0`）作为对照基线与验收素材；该素材仅用于验证，不作为需求来源文档。（用户指定）
- D2：遮挡效果沿用该视频手工基线的口径（39 条手工条目全部为 `color:000000`），自动结果默认同样使用 `color:000000`，仍可在掩膜文件里手工改。（Agent 决定，可被用户否定）
- D3：敏感判定依据为**独立敏感词清单**，不复用 glossary、不对全部汉字打码。（用户确认，Q1）
- D4：百度两个含位置版接口（`accurate_general` 500 次/月、`general` 1000 次/月）额度/可用性用尽后，降级为「无位置版 OCR 读文本 + 算法在帧内定位文字行并按行内字序比例切分」；正常路径下每个被定位的画面只发一次 OCR 请求，并复用工作目录已有的 OCR 文本结果以节省额度。（用户确认，Q2）
- D5：入口为既有 `jpsub mask` 上的新开关（非交互）；结果写独立文件，由既有 `jpsub maskapply` 应用。另一 change 的 `--auto`（自动去人）本 change 分支内不存在，本 change 只新增 `--sensitive*` 参数且仅在 `--sensitive` 为真时生效，不改动其代码路径，两类结果文件互不覆盖。（用户确认，Q3）
- D6：打码粒度为「命中的敏感词整体一个框」，与手工基线的框尺寸同量级。（用户确认，Q4）
- D7：敏感词清单由 Agent 依据手工基线与工作目录 OCR 原文反推一份**初始清单**，作为程序内置默认词表随版本分发（多字词为正式条目；单字通用词如「死」「堕」「雌」默认只作注释示例，避免误盖）；用户可用 `sensitive.txt`（工作目录优先，其次程序目录）替换或维护该清单，也可用 `--sensitive-words <path>` 指定文件。（用户确认 Q5；清单初始内容见完整目标规格）
- D8：打码时间区间以工作目录 `segments.json` 的字幕段为单位：命中段的时间区间 = 该段 `start`/`end` 各外扩一个提前/延后时长（`--sensitive-pad`，默认 0.5s）；相邻段中同一位置同一敏感词合并为一条。打码流程总是发生在 OCR 之后（OCR 原文已存在时不再重复 OCR）。（用户确认，Q6）
- D9：只匹配画面原文（`segments.json` 的 `text`，即画面 OCR 原文，如「肛門」「性的虐待」「調教センター」），不匹配本程序烧录的中文字幕译文。（用户确认，Q7）
- D10：定位模式由 `--sensitive-locate auto|ocr|algo` 控制，默认 `auto`（有含位置版额度则用含位置版 OCR，否则算法）；`algo` 同时用于验证降级路径；`ocr` 用于强制要求含位置版。（Agent 决定，可被用户否定）
- D11：结果文件名固定为 `<工作目录>/.jpsub/masks.sensitive.json`，与手工 `masks.json`、其它 change 的 `masks.auto.json` 互不覆盖。（Agent 决定，可被用户否定）
- D12：验收示例的正样本阈值维持 ≥70%，但先按参考片人工基线补齐词表变体再复测（不因基线未覆盖的条目而下调阈值）；降级路径（A4）改为「可解析 + 框数不少于命中段数一半 + 单刻覆盖面积占比 <15% 不整块覆盖」，不再与 `auto` 路径框数挂钩。（用户裁决：A2「补词表变体后复测，再定阈值」；A4「可解析 + 框数下限 + 不误盖」）

# 验证预期

- 静态/解析级：自动产出文件可被 `jpsub.mask.parse_masks` 解析，字段合法（start<end、w/h>0、effect 合法）。
- 正样本：可被词表解释（存在时间相交且原文含词表词的字幕段）的手工基线条目中，≥70% 在时间与空间上都与自动条目相交（同一文字区域）。参考片实测（`jpsub mask --sensitive`）：词表补入变体后 39 条基线中 38 条可解释，其中 31 条被覆盖 = 82%（60 条自动条目，33 次含位置版请求）。
- 负样本：手工基线未覆盖且 OCR 原文无敏感词的时间段不产生框（参考片实测自动条目 60 条时间全部落在命中段内）；单刻同时覆盖画面面积占比保持在低位（参考片实测最大 5.3%，不整块覆盖）。
- 降级路径：`--sensitive-locate algo` 下仍能产出可被 `parse_masks` 解析的合格掩膜，框数不少于命中段数的一半，框时间全落在含词段内，单刻最大覆盖面积占比 <15%（参考片实测 29 条 / 33 个命中段，最大覆盖 4.3%，全程 0 次 OCR 请求）。
- 端到端：用自动掩膜执行 `jpsub maskapply`，输出视频时长/帧率与原片一致；抽帧可见敏感汉字被遮挡。
- 人工比对：自动结果与人工 `masks.json` 并排抽帧比对，确认无明显误伤，由用户确认。
