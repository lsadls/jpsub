# Outcome

home / edit / mask 三个页面在上一轮按用途分块后，块数偏多（大多 2–3 个按钮）、卡片边框占空间，面板利用率差。本轮把分组数量收敛、视觉改为行内标签式，让按钮区更紧凑；同时修复 mask 页打码列表被挤压变小的问题。

# Scope

- `jpsub/home.py`：① 操作区「对选中项」由 5 块合并为 3 块（编辑与翻译 / 产出与分享 / 删除(不可恢复)），加上「下载(网络)」与「本地视频」合并的「输入」块，共 4 块；全部改为行内标签式。
- `jpsub/edit.py`：「保存与备份」与「还原与备份」合并为一块「保存与还原」；分组视觉改行内标签式。
- `jpsub/mask.py`：右列「导出」块移除，「导出片段」按钮移到左侧按钮区；打码列表放大（占满右列可用高度）；分组视觉改行内标签式。
- `docs/home.md`、`docs/edit.md`、`docs/mask.md`：同步新分组与视觉说明。

## Source coverage

需求来源为用户在会话中的直接陈述（无外部文档）：「对操作面板的利用率太差了」+ 追问确认（涉及页面 home/edit/mask；主要问题是多数块只有两三个按钮浪费空白；edit/mask 的保存与还原应在同一区域；mask 打码列表变小了；mask 导出应放到按钮区）。无逐条来源表。

# Non-goals

- 不改变任何按钮的功能、请求目标与键盘快捷键。
- 不调整预览画面/视频区域的大小逻辑（edit 左侧 min(46vw,80vh) 等保持不变）。
- 不新增或删除按钮（只移动 mask「导出片段」的位置）。
- 不改 settings.py 与命令行行为。

# Acceptance examples

- A1：打开主页，「对选中项」区域的按钮分成 3 个行内标签组：编辑与翻译、产出与分享、删除(不可恢复)；「删除(不可恢复)」组只含删除工作目录与删除视频两个按钮；「下载(网络)」与「本地视频」合并为「输入」组。
- A2：三页所有按钮的 `id` 与 `onclick` 与改动前一致（无丢失、无改名），逐一触发时请求目标不变，页面加载与操作无 JS 报错。
- A3：打开 edit 页，右侧分组中「保存」「还原改动」位于同一行内标签组，分组总数不多于 5。
- A4：打开 mask 页，「导出片段」按钮位于左侧按钮区（不在右列）；右列只有打码列表，列表可视高度不小于改动前（改动前 max-height:66.7vh）。
- A5：三页分组不再使用卡片边框块样式（改动前 `.sec` 的 border/background），改为小号行内标签 + 按钮跟随的紧凑布局。
- A6：`docs/home.md`、`docs/edit.md`、`docs/mask.md` 描述的分组名称与页面实际一致。

# Constraints and invariants

- 删除类操作必须保持独立分组且视觉上危险隔离（红框/警示），不得与其他常用操作混排。
- 行内标签式改造不得引入 JS 报错；键盘快捷键说明（页面底部灰字）同步更新分组名。
- mask 打码列表仍为可滚动列表，行选择行为不变。

# Decisions

- D1（用户选择）：home「对选中项」合并为 4 块总方案——输入（下载+本地视频）/ 编辑与翻译（预览与编辑+翻译）/ 产出与分享（生成字幕/烧录+投稿/复制info/复制tag）/ 删除(不可恢复) 红框独立。
- D2（用户选择）：三页统一改行内标签式：去掉每块卡片边框，标题变小号行内标签（如「编辑：」）后直接跟按钮。
- D3（用户要求）：edit「保存与备份」「还原与备份」合并为一个「保存与还原」组。
- D4（用户要求）：mask「导出」块移出右列并入左侧按钮区；打码列表恢复/放大可视高度。
